Project · Salesforce and AI

CaseAssist

In development

A Salesforce project for AI assisted claims triage in financial services: structured intake, classification support for the handling team, and human approved escalation. CaseAssist is a personal project built to learn in public. It is not a client deployment, and this page separates what is built from what is still being built and what is still an idea.

View the GitHub repository Back to projects

The problem

Claims and service requests arrive unstructured: free text, missing fields, unclear urgency. A person reads each one, decides what it is and where it goes, and that manual triage is slow and inconsistent. The cost is not only time. Inconsistent triage means similar cases are handled differently, and urgent cases wait behind routine ones. CaseAssist explores how much of that first pass a Salesforce build with AI assistance can honestly carry, with a person approving anything that matters.

Guided walkthrough

This walkthrough demonstrates the intended workflow using a sample claim written for this page. It is a simulation of the design. It is not connected to a live Salesforce org, and no real claim data is used.

Step 1 of 4

1. A claim arrives

A policyholder reports water damage from a burst pipe and asks what happens next. The message is free text: no claim type, no severity, no policy reference in a standard place.

Status: intake structure is part of the completed data model.

2. Intake creates a structured case

The intake layer places the claim on a Salesforce case with the fields the handling team needs, so the record can be routed, reported on, and audited like any other case.

Status: data model and core Apex services are complete.

3. Triage support classifies and drafts

The agent layer reads the case and proposes a category, an urgency, and a draft next step for the handler. The handler sees the suggestion and the reasoning surface the design calls for, not a silent decision.

Status: the Agentforce agent layer is in development. This stage is simulated.

4. A person approves escalation

Nothing escalates on the strength of the suggestion alone. A handler reviews the proposal and approves, adjusts, or rejects it, and the case carries that decision forward.

Status: design concept, part of the intended workflow.

What I am learning from this project

Building the data model first changed every later decision for the better: the agent layer has a stable structure to read from, and its suggestions can be checked against real fields instead of free text. The project is also teaching me the discipline of status honesty. An AI feature that is designed is not a feature that works, and saying so plainly is part of the engineering.

What remains

The Agentforce agent layer, the designed escalation workflow, and fuller test coverage as the agent layer matures. Agentforce and Data 360 are technologies I am currently learning, and they are labeled that way everywhere on this site.
