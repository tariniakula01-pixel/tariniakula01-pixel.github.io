Project one · Working demonstration

K-12 Student Data Analytics

Analysis complete

The dataset is a simulated practice dataset sourced online. It holds no real student information. The mess in it was real, though: the tables disagreed on who was enrolled (117 students in one table, 119 attendance rows in another, including students who do not exist in the student table), so I rebuilt the data around one documented population of 110 Active students, logged every cleaning decision, and ran the analysis the same way I would on real school data.

The question behind the project: which students are both below benchmark and chronically absent, and what does that overlap suggest about who needs intervention first?

Percent at benchmark

The SQL, copied from the repository

sql/01_kpi_summary.sql, the headline KPI query (excerpt)

SELECT
    (SELECT COUNT(*) FROM dim_student) AS total_students,
    (SELECT COUNT(*) FROM fact_attendance) AS students_with_attendance,
    (SELECT ROUND(AVG(Attendance_Rate), 2) FROM fact_attendance)
        AS average_attendance_rate,
    (SELECT COUNT(*) FROM fact_assessment) AS students_with_assessment,
    (SELECT ROUND(AVG(Score), 2) FROM fact_assessment) AS average_score,
    (SELECT ROUND(
        100.0 * SUM(CASE WHEN Benchmark = 'Met' THEN 1 ELSE 0 END) / COUNT(*), 1)
     FROM fact_assessment) AS percent_met_benchmark,
    (SELECT COUNT(*) FROM fact_attendance WHERE Is_Chronic_Absence = 'Yes')
        AS chronic_absence_count,
    (SELECT ROUND(
        100.0 * SUM(CASE WHEN Is_Chronic_Absence = 'Yes' THEN 1 ELSE 0 END)
        / COUNT(*), 1)
     FROM fact_attendance) AS chronic_absence_rate;

sql/02_attendance_by_grade_program.sql, chronic absence by grade

SELECT
    CAST(Grade AS VARCHAR) AS group_name,
    COUNT(Attendance_Rate) AS students,
    ROUND(AVG(Attendance_Rate), 2) AS average_attendance_rate,
    ROUND(100.0 * SUM(CASE WHEN Is_Chronic_Absence = 'Yes' THEN 1 ELSE 0 END)
        / COUNT(Attendance_Rate), 1) AS chronic_absence_rate,
    ROUND(AVG(Days_Absent), 1) AS average_days_absent
FROM fact_student_summary
GROUP BY Grade;

sql/03_assessment_performance.sql, benchmark results by grade

SELECT
    CAST(Grade AS VARCHAR) AS group_name,
    COUNT(*) AS students,
    ROUND(AVG(Score), 2) AS average_score,
    ROUND(100.0 * SUM(CASE WHEN Benchmark = 'Met' THEN 1 ELSE 0 END)
        / COUNT(*), 1) AS percent_met,
    SUM(CASE WHEN Benchmark = 'Below' THEN 1 ELSE 0 END) AS students_below
FROM fact_assessment
GROUP BY Grade;

Three DAX measures, copied from powerbi/dax_measures.md

Chronic Absence Count =
CALCULATE (
    COUNTROWS ( fact_attendance ),
    fact_attendance[Is_Chronic_Absence] = "Yes"
)
-- Returns 36 on the current data.

Percent Met Benchmark =
DIVIDE ( [Students Met Benchmark], [Students With Assessment] )
-- Returns 75.7 percent. The denominator is the 107 assessed students.

Chronic Absence Rate =
DIVIDE ( [Chronic Absence Count], [Students With Attendance] )
-- Returns 33.3 percent. The denominator is the 108 students with attendance.

CaseAssist, the implemented Salesforce build

Data model and Apex services implemented Agentforce agent layer in development Intake shown here is a simulation

CaseAssist is a personal Salesforce project for claims intake and triage. What is implemented today is the data model and three Apex services, each with its own test class: ClaimCreationService, which creates a Claim__c record linked to a policy with its status defaulting to New; PolicyLookupService; and ClaimRiskClassifier, a rule-based classifier written in Apex. The agent layer described in the repository README is still in progress.

Run the classifier

This is a JavaScript copy of my Apex classifier. Same five rules, same order, and it tells you which rule decided the result. It is not connected to a Salesforce org, and it is not an AI model. The Apex code itself notes that a future version would use an AI scoring model; that version does not exist yet.

Blank is a real test case. The classifier treats a missing amount as its own rule.

The rules of ClaimRiskClassifier, in the order the Apex evaluates them

1. Policy Status__c is not Active        -> High
2. Estimated_Amount__c is blank          -> Medium
3. Estimated_Amount__c is 10000 or more  -> High
4. Estimated_Amount__c is 2000 or more   -> Medium
5. Otherwise                             -> Low

Try the boundary cases: an Inactive policy at any amount, an Active policy with a blank amount, 10000 exactly, 2000 exactly, and 500. Each one lands on a different rule.

One requirement

BR-002 (High priority): Leadership needs to monitor appointment completion, cancellation, and no-show rates.

FR-003 follows from it: the solution shall calculate cancellation and no-show rates. Eight business requirements and fourteen functional requirements are documented this way in business-analysis/requirements.md.

One user story, US-002: Analyze Missed Appointments

As a clinic manager, I want to analyze cancellation and no-show patterns by specialty, location, and appointment type, so that I can identify areas with higher levels of missed appointments.

Acceptance criteria

  • Cancellation and no-show rates can be compared across specialties.
  • Cancellation and no-show rates can be compared across locations.
  • Appointment types can be analyzed separately.
  • Results clearly identify higher-performing and lower-performing segments.
  • The analysis uses a consistent calculation method.

What the analysis found

The findings come from the project's synthetic appointment dataset, and the insights document treats them as associations, not causes.

  • Appointments scheduled 31+ days in advance show the highest combined missed-appointment activity, with no-show and cancellation rates both higher than shorter lead-time groups.
  • Dermatology has the highest observed no-show rate of the specialties analyzed, followed by Pediatrics and Primary Care.
  • Patient satisfaction decreases across the wait-time categories, from the highest among patients waiting 15 minutes or less to the lowest among patients waiting more than 60 minutes.
