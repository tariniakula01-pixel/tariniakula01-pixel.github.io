Project two · Guided demonstration

CaseAssist, the implemented Salesforce build

Data model and Apex services implemented Agentforce agent layer in development Intake shown here is a simulation

CaseAssist is a personal Salesforce project for claims intake and triage. What is implemented today is the data model and three Apex services, each with its own test class: ClaimCreationService, which creates a Claim__c record linked to a policy with its status defaulting to New; PolicyLookupService; and ClaimRiskClassifier, a rule based classifier written in Apex. The agent layer described in the repository README is still in progress, and this page says so wherever it appears.

The data model, exactly as implemented

Policy__c

  • Status__c

The policy a claim belongs to. Its status drives the first rule of the classifier.

Claim__c holds a
lookup to Policy__c
→

Claim__c

  • Related_Policy__c, lookup to Policy__c
  • Description__c
  • Incident_Date__c
  • Estimated_Amount__c
  • Claim_Status__c

Run the classifier

This is a web simulation of the implemented Apex logic. It runs the real rules of ClaimRiskClassifier, in the real order, and tells you which rule decided the result. It is not connected to a Salesforce org, and it is not an AI model. The Apex code itself notes that a future version would use an AI scoring model; that version does not exist yet.

Blank is a real test case. The classifier treats a missing amount as its own rule.

The rules of ClaimRiskClassifier, in the order the Apex evaluates them

1. Policy Status__c is not Active        -> High
2. Estimated_Amount__c is blank          -> Medium
3. Estimated_Amount__c is 10000 or more  -> High
4. Estimated_Amount__c is 2000 or more   -> Medium
5. Otherwise                             -> Low

Try the boundary cases: an Inactive policy at any amount, an Active policy with a blank amount, 10000 exactly, 2000 exactly, and 500. Each one lands on a different rule, which is the fastest way to see that the simulation follows the Apex and not a guess.
